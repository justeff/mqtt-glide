# Fuzzing

Fuzz targets for the MQTT 5 codec, built with [cargo-fuzz](https://github.com/rust-fuzz/cargo-fuzz)
(nightly Rust). This crate is not part of the library workspace or the published package.

| Target | Feeds | Checks |
|--------|-------|--------|
| `decode_frames` | Arbitrary bytes as they could arrive from a broker, split into arbitrary reads, with an arbitrary inbound size limit | No panic; the decoded frames and the first error do not depend on read boundaries; every decoded frame re-encodes and decodes back to itself |

```shell
cargo install cargo-fuzz
cd fuzz
cargo +nightly fuzz run decode_frames -j 6 -- -max_total_time=600 -max_len=4096
```

CI runs each target for 60 s per push, starting from the committed seeds and a corpus cached
between runs. A crash leaves its input under `artifacts/<target>/` (CI uploads it as the
`fuzz-artifacts` artifact); reproduce it with
`cargo +nightly fuzz run <target> artifacts/<target>/<file>`, then add it as a regression test
next to the codec unit tests.

## Seed corpus

`seeds/decode_frames/` holds one valid frame per packet shape (every packet type, short and long
ack forms, property-heavy and topic-alias PUBLISH) plus a few multi-frame streams. CI and local
runs pass it as an extra corpus dir after the working one, so new inputs land in `corpus/` and
the seeds stay untouched:

```shell
cargo +nightly fuzz run decode_frames corpus/decode_frames seeds/decode_frames -- -max_len=4096
```

The seeds are generated by `examples/gen_seeds.rs`, which spells out the wire bytes and checks
each one against the decoder. After a codec change that invalidates a seed, or to add one, run
from `fuzz/`:

```shell
cargo run --example gen_seeds
```
